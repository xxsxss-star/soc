SOC Alert Triage

告警研判

AlertLens 是一个 SOC 告警误报分层研判 Demo。系统通过证据聚合、规则分流和 AI 辅助分析完成告警研判。我们明确限定了模型的能力边界：AI 只负责分析复杂证据并提供建议，最终结果仍需经过输出校验、决策路由和人工复核，从而保证研判过程安全、可控、可追溯。

4 类标准化证据
3 层研判机制
30 秒项目介绍

这个项目解决的是 SOC 初筛中“上下文分散、误报重复判断、AI 结论不可控”的问题。核心不是训练一个分类模型，而是设计了一条安全优先、可解释、失败可降级的研判工作流。

01 / PROBLEM

系统真正解决什么问题？

面对一条“内网主机连接可疑 IP”的告警，分析师不能只看原始严重级别，需要同时核对资产、工单、情报与行为。AlertLens 将这段重复劳动标准化。

01

上下文分散

资产信息、授权工单、威胁情报和 EDR 行为分布在不同系统。

统一证据包
02

误报重复判断

授权扫描等明确场景反复依赖人工检查，消耗分析师时间。

规则自动分流
03

AI 容易越界

自由文本可能引用不存在的信息，分数也不等于真实准确率。

Schema + 引用校验
04

错误关闭代价高

一旦把真实攻击当成误报关闭，可能错过横向移动或数据外传。

高风险优先否决
02 / WORKFLOW

一条告警如何走完整条链路

工作流由 LangGraph 编排，每个节点保留时间线与状态。规则路径不会调用 AI；AI 调用或校验失败时安全降级到人工。

01加载告警读取告警必要字段，建立本次 run。
02聚合证据CMDB、审批工单、威胁情报、EDR 行为。
03规则分流按高风险、数据质量、明确误报、AI 入口排序。
04受约束 AI仅处理无法确定或互相冲突的证据。
05决策与兜底自动确认、人工补充、高优先级调查。
03 / RULE ENGINE

为什么规则必须有优先级？

授权不是“免死金牌”。系统先查高风险迹象，再看数据是否足够，最后才允许授权扫描被确认为误报。

安全优先级

1
高风险否决先保护漏报风险
2
数据质量检查阻止残缺证据推断
3
明确误报确认所有条件同时满足
4
复杂场景进入 AI只分析未决与冲突
R-001 / R-003 / R-005高风险否决

横向移动、数据外传、核心资产连接已知恶意目标 → 高优先级人工调查。

R-201 / R-202数据质量规则

关键字段缺失，或资产与行为证据同时缺失 → 人工补充，不让 AI 猜。

R-101授权扫描确认

扫描资产 + 有效授权 + 时间和目标在范围内 + 无恶意情报与行为冲突 → 规则确认误报。

R-301 / R-302 / R-399AI 入口规则

未授权恶意通信、授权与证据冲突、其他无法确定场景 → 进入受约束 AI。

04 / GUARDED AI

AI 负责归纳，不负责拍板

AI 只能基于输入证据给出结构化建议。输出随后还要经过格式、分数和证据引用三层校验。

六条硬约束

  1. 只能依据输入告警和标准化证据。
  2. 不能补充输入中不存在的事实。
  3. 每条理由必须引用真实 evidence_id。
  4. 证据不足必须明确输出“证据不足”。
  5. 只能提出建议，不能修改状态或调用处置工具。
  6. 严格返回 Schema，四项分数各 0～25。

05 / DECISION

处置模块不盲读 AI 结论

决策路由同时查看规则结果、AI 建议、校验错误和阈值。默认阈值为 85，任何异常都转人工。

07 / SCOPE

主动讲清 Demo 边界

边界讲清楚不是减分项，反而说明你知道从 Demo 到生产还差哪些工程能力。

当前已实现

  • FastAPI 后端与 Streamlit 演示界面
  • 四类本地模拟数据的证据聚合
  • 安全优先的确定性规则引擎
  • Mock / Live 两种 AI 分析器
  • AI 结构、分数、证据引用校验
  • LangGraph 工作流、时间线与人工决定

当前刻意不做

  • 不连接真实 SOC、CMDB、EDR、情报平台
  • 不执行封禁、隔离、关单等不可逆操作
  • 没有认证、数据库和跨进程任务队列
  • 状态保存在单进程内存，重启后清空
  • AI 分数未用真实生产数据校准
  • 不宣称 Demo 指标等同生产准确率
